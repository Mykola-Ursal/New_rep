# Кандидатные кейсы — `compound` (дополнение к CMP-01)

Статус: **draft, не прогнано**. CMP-01 уже в реальном `test-plan.md` (IDOR,
`has_one = owner`). Ниже — остальные пункты того же стандартного чек-листа
подмен, которые для `compound` пока не написаны, плюс проверка того, реально
ли двигаются токены между `reward_vault`/`stake_vault` при компаунде (это важно
для инвариантов пула — см. `test-plan-pool-invariants.md`, INV-04).

## Как использовать

CMP-06 — сделать первым в этом наборе: ответ на него определяет, актуальны ли
CMP-08 (арифметика трансфера) и нужно ли расширять INV-01/04 отдельной веткой
именно для `compound`, где токены могут не двигаться физически между vault'ами.
